# Universal CAN Monitor - 사용자 매뉴얼 (R012_1)

이 문서는 Universal CAN Monitor의 주요 기능과 사용법을 상세히 설명합니다.

## 통합 설정 및 메뉴바 (2026-09-29 추가)

- **파일 → 통합 설정 저장…** (`Ctrl+Shift+S`): BUS 1·2·3의 DBC/SYM 원문, TX 목록, CAN 설정, 실시간 그래프와 UserPanel 전체를 하나의 `.pjjsettings` 파일로 저장합니다. 원본 DB 파일을 옮기거나 삭제해도 이 파일만으로 복원할 수 있습니다.
- **파일 → 통합 설정 불러오기…** (`Ctrl+Shift+O`): 파일 전체를 먼저 검증하고 기존 설정을 교체합니다. 검증 오류이면 기존 설정과 창을 유지합니다. 비어 있는 항목도 그대로 적용되므로 이전 항목이 남지 않습니다.
- 그래프는 창별 제목·범례 이름/순서·색상·선 종류·표시 여부·수식·창 위치/크기를 보존합니다. 통합 뷰에 포함된 그래프도 **개별 창, Sync OFF**로 복원됩니다. 저장할 때 현재 화면의 Sync 상태는 바뀌지 않습니다. 이전 파형·측정 태그·트리 수신값·횟수는 복원하지 않습니다.
- UserPanel은 페이지·도구·배치·등록 패킷·Init/시퀀스·신호 연결을 포함합니다. 닫힌 패널의 구성도 보존하며 복원 모드는 **STANDARD(송신 정지)**입니다. RUN/시퀀스 실행을 자동 재개하지 않습니다.
- 불러올 때 TX, UserPanel, 로그 재전송을 모두 정지하고, **기존 로그뷰 본창과 개별·통합 로그 그래프를 모두 닫습니다.** 로그 원본은 삭제하지 않습니다. 진행 중이던 기록은 사용자 데이터 폴더의 `Log` 하위에 저장합니다.
- Windows는 저장 당시 Open이었던 BUS를 다시 연결합니다. Linux는 이전 연결 상태와 관계없이 모든 BUS를 Close로 시작하며 장치 선택과 속도 설정만 복원합니다. 장치를 찾지 못한 경우에도 BUS는 Close이고 저장 설정은 보존됩니다. 수동 불러오기에서는 복원 결과를 알리며, 시작 자동 복원에서는 장치 미검색 알림을 생략합니다.
- **데이터베이스 → BUS별 내보내기 / 전체 DB 내보내기…**: 등록 당시 원문을 BUS별 하위 폴더에 추출합니다. 같은 파일명이 있으면 번호를 붙여 기존 파일을 보존합니다. `등록 해제`는 원본 파일 삭제가 아닙니다.
- **송신 → 전체 송신 정지** (`Ctrl+Shift+X`): CAN 연결을 유지하면서 TX·UserPanel·로그 재전송을 모두 멈춥니다.
- `CAN`, `송신`, `보기` 메뉴는 기존 화면 버튼 기능을 함께 제공합니다. `도움말`에서는 설명서와 프로그램 정보를 볼 수 있습니다. 뷰어 전용 모드에는 CAN/TX/통합 설정 변경 메뉴가 표시되지 않습니다.

### 자동 복원 및 저장 위치

자동 복원 파일은 실행 파일 옆이 아닌 사용자 데이터 폴더의 `PCAN_Viewer_JJ/session.pjjsettings`에 저장됩니다. Windows에서는 일반적으로 `%LOCALAPPDATA%\PCAN_Viewer_JJ`이며, Linux에서는 `$XDG_DATA_HOME/PCAN_Viewer_JJ` 또는 `~/.local/share/PCAN_Viewer_JJ`입니다. 변경 상태를 약 5초 간격과 정상 종료 시 저장하므로 재빌드 시 dist 정리에 영향을 받지 않습니다.

새 자동 복원 파일이 없을 때만 기존 `PCAN_Viewer_JJ.pk`를 읽어 이전 설정을 가져옵니다. 기존 파일은 삭제하지 않습니다. 자동 복원 파일이 손상되면 오류를 표시하고 자동 덮어쓰기를 중지합니다. 정상 통합 파일을 불러오거나 통합 저장에 성공하면 자동 저장을 다시 사용합니다.

통합 저장은 설정을 위한 기능이며 수신 로그 자체의 백업 기능은 아닙니다. 수식은 숫자, `X1` 등 신호 변수, `Y1`~`Y3`, 산술·비교 연산을 지원합니다. 외부 함수 호출이나 Python 코드 실행은 지원하지 않습니다.

## 1. 화면 구성

프로그램의 메인 화면은 크게 4개의 영역으로 구성됩니다.

- **① Connection Control**: CAN 하드웨어 채널을 선택하고 통신을 시작/종료하는 영역입니다.
- 메인창의 **파일 → 새 화면**은 통신 연결, DBC, 송수신 패킷, 그래프와 유저패널을 초기화합니다. 저장되지 않은 기록은 먼저 보존하며, 초기화된 상태는 자동 설정 저장에 반영됩니다.
- 유저패널의 **File → New Panel**은 패널의 도구·등록 TX 패킷·INIT·페이지·편집 이력을 초기화합니다. 메인창의 연결과 DBC는 유지됩니다.
- 유저패널 제목은 해당 창의 **File → Rename Panel…**에서 변경합니다. 제목은 패널 파일·패키지·통합 설정에 함께 저장됩니다.
- **② Database Files**: 통신 데이터를 해석하기 위한 `.dbc` 또는 `.sym` 파일을 로드하고 관리하는 영역입니다.
- **③ Monitoring Tree (수신부)**: CAN 버스에서 수신된 메시지와 시그널의 값을 실시간으로 보여주는 영역입니다.
- **④ Tx Panel (송신부)**: CAN 메시지를 생성하고 버스로 전송하는 패널입니다.

## 2. 기본 사용법

### 채널 연결
1.  **Connection Control** 패널에서 연결할 **Bus**를 선택합니다. (4개 채널 동시 지원)
2.  BUS별로 **CAN 방식**을 고른 뒤, 그 방식으로 검색된 CAN 하드웨어 채널과 통신 속도(Baudrate)를 선택합니다.
    - Windows: **PCAN** (PCAN-Basic 드라이버). Kvaser, 범용(python-can) 방식은 추후 추가 예정입니다.
    - Linux: **SocketCAN** (`can0`, `can1` …, 테스트용 `vcan0`). 장치 제조사와 관계없이 커널 드라이버로 잡힌 인터페이스를 사용합니다.
    - CAN 방식은 연결 중에는 바꿀 수 없으며, 통합 설정에 BUS별로 저장됩니다. 이전 설정 파일은 저장된 장치 종류로 방식을 판단합니다.
3.  **CAN FD** 통신인 경우, FD 옵션을 활성화하고 데이터 통신 속도(Data Baudrate)를 설정합니다.
4.  **Open** 버튼을 눌러 통신을 시작합니다. 연결에 성공하면 버튼이 비활성화되고 **Close** 버튼이 활성화됩니다.
5. Linux SocketCAN은 일반 사용자로 실행할 수 있습니다. 인터페이스 설정에 권한이 필요하면 앱에서 sudo 비밀번호 대화상자를 띄웁니다. sudo 인증 캐시가 살아 있으면 다시 묻지 않으며, 입력한 비밀번호는 연속 명령을 위해 최대 60초만 메모리에 두고 버립니다. 파일이나 로그에는 저장하지 않습니다. Windows에는 이 대화상자가 없습니다.

- 연결 설정은 행 번호가 BUS 번호인 4행 그리드입니다. 행 정렬과 이동은 지원하지 않습니다. 버스 설정은 송신 패킷 표에 맞춘 조밀한 행과 작은 글꼴을 사용하며, 속도 표기는 기존 설정을 유지합니다.
- **Open / Close**는 실제 연결 결과에 따라 바뀌는 단일 버튼입니다. 연결 중에는 해당 BUS의 장치 검색과 설정 편집이 잠깁니다. Reset 버튼은 제공하지 않습니다.
- **State**는 현재 상태 또는 주요 오류를 한 줄로 표시합니다. 오른쪽 **…** 버튼에서 BUS별 시간순 로그와 오류 진단을 확인하고 복사·저장할 수 있습니다. PCAN의 CAN 경고와 Bus-Off 상태도 확인하며, Bus-Off는 해당 BUS를 해제합니다.
- 연결 해제는 해당 BUS의 메인 TX, 패널 주기 송신과 관련 시퀀스를 정지합니다. 로그 재생은 다른 BUS로 전송되는 것을 방지하기 위해 정지합니다. 다시 연결해도 송신 작업은 자동 재개하지 않습니다. 해당 BUS의 수신 값·통계는 재연결 시 초기화되고 DBC·패킷·패널 설정은 유지됩니다.
- **CAN Settings**와 **Database Files (.dbc, .sym)** 제목의 화살표로 설정 영역을 접고 펼칩니다. 송신부 높이는 유지하고 수신부 높이가 조절됩니다. 접힘 상태는 통합 설정에 저장되며 DBC 해석과 로그 열기는 계속 사용할 수 있습니다.
- 사용자 패널의 **통신 설정 / DBC** 창도 같은 4채널 그리드와 연결 상태를 공유합니다. 통신 설정을 변경하면 패널은 STANDARD로 전환됩니다.
- 통합 설정 저장 형식은 v2입니다. 기존 v1 3채널 설정을 읽으면 BUS 1~3과 패널 참조를 유지하고 빈 BUS 4를 추가합니다. 최초 변환 시 원본을 `.v1.bak` 파일로 보관합니다. 과거 실행 파일은 새 v2 파일을 읽지 못하므로 이전 버전으로 돌아갈 때는 백업본을 사용하세요.

### 데이터베이스(DBC/SYM) 적용
1.  **Database Files** 패널에서 해당 버스에 맞는 **Load DBC/SYM** 버튼을 클릭하여 파일을 선택합니다.
2.  파일이 성공적으로 로드되면 목록에 파일명이 표시됩니다.
3.  이제 수신부(Monitoring Tree)에서 CAN ID 대신 메시지 이름이 표시되고, 하위에 시그널들이 나타납니다.

> **💡 .sym 파일 호환성 정보**
> PEAK-System의 `.sym` 파일은 포맷 버전 5.0과 6.0을 모두 지원합니다. 프로그램이 파일 내용을 분석하여 버전을 자동으로 감지하고 파싱하므로 사용자는 확장자만 맞으면 자유롭게 로드할 수 있습니다.

### 데이터 수신 및 분석
-   **Monitoring Tree**에서는 수신된 메시지가 CAN ID를 기준으로 그룹화되어 표시됩니다.
-   DBC 파일이 적용된 경우, 메시지 이름과 그 하위의 시그널 목록이 트리 형태로 나타납니다.
-   **Value** 컬럼에서 메시지의 Raw Data(16진수) 또는 각 시그널의 물리 값(Physical Value)을 실시간으로 확인할 수 있습니다.
-   서로 다른 CAN ID에 같은 이름의 신호가 있어도 BUS·CAN ID·신호명을 구분하여 값을 표시합니다. Enum·소수점 정밀도·단위도 해당 메시지의 정의를 사용합니다.
-   **Cycle (ms)** 과 **Count** 컬럼을 통해 메시지 수신 주기와 횟수를 파악할 수 있습니다.
-   **일괄 선택**: 메시지 이름(부모 항목)의 체크박스를 선택하면 하위의 모든 시그널이 한 번에 선택/해제됩니다.
-   수신부 옆 **RX**와 송신부 옆 **TX** 표시를 더블클릭하면 해당 영역의 트리를 전체 접기 / 전체 펼치기로 전환합니다. 펼쳐진 메시지가 있으면 전체를 접고, 모두 접혀 있으면 하위 항목까지 모두 펼칩니다. 두 영역은 독립적으로 동작합니다.
-   **정렬**: 메인창 수신부는 기본으로 **Bus 번호 → CAN ID 순**으로 정렬됩니다. **Bus** 제목을 누르면 같은 버스 안에서도 CAN ID 숫자 순서로 정렬하며, 새 패킷도 해당 위치에 추가됩니다. 다른 열 제목을 누르면 그 열의 값으로 정렬하고, 같은 제목을 다시 누르면 오름차순·내림차순을 전환합니다. Cycle·Count·숫자 신호값은 숫자 크기로 정렬합니다.

## 3. 송신 기능 (Tx Panel)

메인 창 하단의 송신 패널에서는 CAN 메시지를 직접 만들어 버스로 보낼 수 있습니다.

### 패킷 생성 및 수정
1.  **Create Packet** 버튼을 눌러 패킷 생성 창을 엽니다.
2.  **CAN ID / Symbol** 항목에서 DBC 파일에 정의된 심볼(메시지 이름)을 선택하거나, CAN ID를 직접 16진수로 입력할 수 있습니다.
    -   심볼을 선택하면 ID, Length, Type이 자동으로 채워지고 하단에 시그널 표가 나타납니다.
    -   시그널 표의 **Value** 셀에 원하는 물리 값을 입력하면, 상단의 **Data (HEX)** 가 자동으로 계산됩니다.
3.  **Data (HEX)** 필드에 직접 16진수 데이터를 입력할 수도 있습니다. 이 경우, 시그널 표의 값들이 반대로 자동 계산되어 표시됩니다.
4.  생성된 패킷을 수정하려면 목록에서 해당 항목을 **더블클릭**하세요. 편집 확인 또는 취소 후에도 하위 신호 트리의 펼침·접힘 상태가 유지됩니다. 펼침 화살표로 직접 상태를 변경할 수 있습니다.

### DBC 신호 CRC-8 / CRC-16
- DBC Signals의 **자동 증감 / CRC**에서 `CRC-8` 또는 `CRC-16`을 선택하고 옆 셀의 **CRC 설정** 버튼을 누릅니다. CRC-8은 8비트, CRC-16은 16비트 정수 신호에 적용합니다.
- 연산 범위는 **0부터 시작하는 바이트 번호와 사이즈**로 지정합니다. 예를 들어 2~31바이트는 시작 `2`, 사이즈 `30`입니다.
- **추가 연산 데이터**는 범위 뒤에 붙이는 고정 HEX 바이트입니다. `0x0000` 또는 `00 00`은 0인 바이트 두 개를 추가합니다. `12 34`는 입력 순서 그대로 붙습니다.
- `poly`, `init`, `xorout`은 HEX 값으로 입력합니다. Poly는 최상위 항을 제외한 정방향 다항식이며, RefIn/RefOut은 각각 입력 바이트/최종 CRC의 비트 반전을 지정합니다.
- 카운트 값 반영 후 매 전송마다 CRC를 계산합니다. 결과에는 Factor/Offset을 적용하지 않습니다. CRC-16은 설정창에서 **LSB 먼저 (Intel)** 또는 **MSB 먼저 (Motorola)**를 선택합니다. 예: `0x1234`의 결과는 각각 `34 12`, `12 34`입니다. DBC 신호의 비트 위치는 유지하며, 입력 데이터 순서와 RefIn/RefOut 설정은 영향을 받지 않습니다. 이전 저장 설정은 기존 DBC 순서를 유지합니다.
- 연산 범위에 CRC 신호 자신의 비트가 포함된 바이트가 하나라도 있으면 등록 오류를 표시합니다. 길이 초과, 잘못된 파라미터, CRC 간 순환 참조도 허용하지 않습니다.
- 설정은 패킷 편집, 자동 저장 파일 및 XMT 저장/불러오기에서 유지됩니다. 기존 `Hyundai_CRC` 패킷 타입 대신 DBC 신호 CRC를 사용할 때는 패킷 타입을 **적용 안함**으로 둡니다.

### 패킷 타입 (Hyundai_CRC)
-   **패킷 타입** 콤보박스에서 `Hyundai_CRC`를 선택할 수 있습니다.
-   이 타입을 선택하면, 사용자가 **Data (HEX)** 필드에 어떤 값을 입력하든 상관없이, 실제 패킷이 전송되는 시점에 프로그램이 내부적으로 아래 규칙에 따라 데이터의 앞 3바이트를 덮어씁니다.
    -   `Data[0]`, `Data[1]`: CRC-16 CCITT-FALSE 값 (Little Endian)
    -   `Data[2]`: 0~255까지 순환하는 Alive Counter 값
-   사용자는 CRC와 Alive Count를 제외한 실제 유저 데이터(3번 바이트부터)만 신경 써서 입력하면 됩니다.

### 패킷 전송 및 관리
-   **단발 전송**: 목록에서 전송할 패킷을 선택하고 키보드의 **스페이스바**를 누르면 1회 전송됩니다.
-   **주기 전송**:
    -   패킷 생성 시 **Cycle Time**을 0보다 큰 값(ms)으로 설정합니다.
    -   목록의 **Action** 컬럼에 있는 **Start** 버튼을 누르면 설정된 주기로 자동 전송이 시작됩니다.
    -   전송 중에는 버튼이 **Stop**으로 바뀌며, 클릭 시 전송을 멈출 수 있습니다.
    -   메인 TX와 유저 패널의 주기 송신은 공통 스케줄러를 사용하는 BUS별 백그라운드 스레드에서 처리합니다. 화면 갱신·로그 기록을 송신 경로에서 분리하고, 매번 이전 목표 시각에 주기를 더해 누적 오차를 줄입니다. 놓친 주기는 몰아서 보내지 않고 원래 주기 기준의 다음 시각으로 건너뜁니다.
    -   로그 재생을 시작해도 메인/패널 주기 송신은 유지됩니다. 같은 BUS가 송신 중이거나 주기 송신 예정 시각에 가까우면 로그 선택/연속 전송이 기다립니다. 이미 드라이버에 전달된 프레임과 CAN 중재를 선점하지는 않습니다. 지연·누락은 BUS 로그의 `TX 주기 지연` 경고로 확인합니다.
    -   Windows에서는 주기 송신 작업이 있는 동안 1ms 타이머 해상도를 요청하고 작업이 끝나면 해제합니다. 이는 1ms 정확도 보장이 아니며, 운영체제 스케줄링·드라이버·버스 부하에 따른 오차는 실제 장비에서 확인해야 합니다.
-   **관리 단축키**:
    -   **삭제**: `Delete` 키
    -   **복사/붙여넣기**: `Ctrl+C`, `Ctrl+V` (여러 항목 동시 선택 가능)
-   **목록 저장/불러오기**: **Load/Save Tx List** 버튼을 통해 현재 패킷 목록을 `.xmt` 파일로 저장하거나 불러올 수 있습니다.

## 4. 실시간 그래프

수신부 트리에서 원하는 시그널을 선택하여 실시간으로 값이 변하는 모습을 그래프로 확인할 수 있습니다.

### 그래프 열기
1.  수신부(Monitoring Tree)에서 그래프로 보고 싶은 시그널 이름 앞의 **체크박스를 선택**합니다. (여러 개 선택 가능)
2.  **[View Real-time Graph for Selection]** 버튼을 클릭하면 선택된 모든 시그널이 하나의 그래프 창에 표시됩니다.
3.  그래프가 열리면 수신부 트리의 메시지·신호 체크가 모두 해제됩니다. 다음 그래프에 표시할 신호를 새로 선택하면 됩니다.

### 주요 기능
- **Reset Zoom**: 최신 데이터 기준 최근 30초를 표시하고 해당 구간의 Y축 범위를 자동 조정합니다. **Auto Y**가 켜져 있으면 현재 X축에 보이는 데이터에서 Y값이 범위를 넘을 때 자동으로 확장합니다. Y축 수동 고정을 원하면 Auto Y를 끄세요.
- **실시간 통합 그래프**의 Reset Zoom도 모든 그래프를 같은 최근 30초 구간으로 맞춥니다. **Fit All Data**는 메모리에 보관된 전체 데이터 구간을 표시합니다. 통합 그래프에서 한 플롯의 X축을 이동/확대하면 나머지 플롯도 같은 시간 범위를 사용합니다.
-   **범례 (Legend)**: 그래프 우측의 범례 항목을 **더블클릭**하면 해당 시그널의 그래프를 잠시 숨기거나 다시 표시할 수 있습니다.
-   **태그 (Tags)**:
    -   그래프 위의 특정 지점을 **클릭**하면 해당 위치의 시간과 값을 보여주는 태그가 고정됩니다.
    -   범례에서 여러 시그널을 선택(클릭 또는 Ctrl+클릭)한 상태로 그래프를 클릭하면, 선택된 모든 시그널에 대한 태그가 동시에 생성됩니다.
    -   생성된 태그를 다시 클릭하면 삭제됩니다.
-   **X축 동기화 (Sync X-Axis)**: 새로 여는 실시간·로그 그래프는 기본으로 동기화가 켜져 있습니다. 하나의 창에서 줌(Zoom)하거나 화면을 이동(Pan)할 때 다른 모든 동기화된 창의 X축이 함께 움직입니다. 창 크기를 조절해도 동일하게 적용되며, 각 창의 Sync 버튼으로 해제할 수 있습니다.
-   통합보기 도구 모음 **오른쪽 끝**에는 두 종료 버튼이 있습니다. **통합보기 종료**는 낱개 그래프 창으로 전환하고, 전원 아이콘인 **그래프 종료**는 통합 창과 포함된 그래프를 모두 닫습니다. 창 제목줄의 **X**도 낱개 창을 띄우지 않고 그래프를 모두 종료합니다.
-   **레이블/스타일 수정 (Edit Labels)**:
    -   그래프의 제목과 각 범례의 표시 이름을 사용자가 원하는 텍스트로 변경할 수 있습니다.
    -   범례 목록에서 원하는 항목을 **마우스로 드래그**하여 순서를 바꿀 수 있습니다.
    -   각 시그널의 **선 색상**과 **선 종류**(실선, 점선 등)를 직관적으로 변경할 수 있습니다.
-   **사용자 정의 수식 (Formula)**:
    -   **Formula** 버튼을 눌러 그래프에 표시된 시그널들을 변수(X1, X2...)로 사용하여 새로운 가상 시그널(Y1, Y2, Y3)을 만들 수 있습니다.
    -   예: `X1 + X2` 또는 `(X1 - 5) * 10` 과 같은 사칙연산을 지원합니다.
-   **스크린샷 (Screenshot)**: 현재 그래프 뷰를 이미지 파일(.png)으로 저장합니다. X축 동기화가 켜져 있으면 모든 동기화된 그래프를 하나의 긴 이미지로 합쳐서 저장합니다.
-   **Close Graphs**: 메인창 수신부 도구 모음 오른쪽에는 **Close Graphs → Clear Data → Record** 순서로 배치됩니다. 로그뷰는 DBC 탭의 그래프 도구 모음 오른쪽 끝에 **Close Graphs**가 있습니다. 각 버튼은 해당 창에서 연 낱개·통합 그래프를 모두 닫습니다.

## 5. 로그 기록 및 뷰어

### 데이터 기록 (Record)
-   CAN 채널이 하나 이상 열려있는 상태에서 메인 창의 **Record** 버튼을 누르면 기록 창이 나타납니다.
-   이때부터 수신되는 모든 CAN 메시지는 PEAK-System의 `.trc` 포맷으로 기록됩니다.
-   기록 중인 로그는 메모리가 아니라 임시 파일에 실시간으로 쌓이므로, 장시간 기록해도 메모리가 늘지 않습니다.
-   **Save**: 저장 위치를 골라 저장한 뒤 창을 닫습니다. 저장 대화상자에서 취소하면 기록을 계속합니다.
-   **Close** 버튼: 저장하지 않고 닫으며 임시 파일을 삭제합니다.
-   창의 X 버튼 또는 프로그램 종료: 기록이 있으면 `[프로그램 폴더]/Log/`에 자동 저장한 뒤 임시 파일을 삭제합니다.
-   `$STARTTIME`은 첫 프레임 시각 기준이라, 다시 불러와도 절대시간이 맞습니다. 29bit ID는 DBC 정의를 따라 8자리로 기록됩니다.

### 로그 뷰어 (Log Viewer)
-   **Open CAN Log Viewer** 버튼을 클릭하여 저장된 `.trc` 파일을 엽니다.
-   지원 형식: PEAK TRC 1.0 / 1.1 / 1.2 / 1.3 / 2.x(CAN FD 포함), CL2000 로거 TXT. 8자리로 기록된 ID는 29bit(Extended)로 재전송합니다.
-   로그 뷰어는 파일을 열 때 **메인 창에 현재 로드된 DBC/SYM 파일**을 기준으로 로그를 해석하여 분석 결과를 보여줍니다.

#### 로그 뷰어 기능
-   **DBC 탭**:
    -   로그 파일에서 발견된 메시지 및 시그널 목록을 보여줍니다.
    -   여기서 시그널을 체크하고 **View Graph** 버튼을 누르면, 로그 전체 기간에 대한 **정적 그래프**를 볼 수 있습니다. 그래프가 열리면 메시지·신호 체크가 모두 해제됩니다. (실시간 그래프와 기능 동일)
    -   로그 그래프의 **Combined View**에서 **Reset Zoom**과 **Fit All Data**는 모든 참여 그래프의 전체 로그 시간 구간으로 X축을 맞추고, Y축은 각 그래프의 데이터에 맞게 자동 조정합니다. 로그 데이터가 비어 있거나 시점이 하나뿐인 경우도 지원합니다.
-   **LOG 탭**:
    -   `.trc` 파일의 원본 내용을 표 형태로 보여줍니다.
    -   첫 줄에는 **전송**, **선택 전송**, **반복**이 있으며 **Save**는 오른쪽 끝에 있습니다. 둘째 줄에는 CAN 버스 선택과 CAN ID 범위, **필터** 버튼이 있습니다.
    -   **필터**: CAN 버스(`ALL`, `BUS1`~`BUS4`)를 선택하고 시작·끝 CAN ID를 16진수로 입력한 뒤 필터를 켭니다. 버스와 ID 범위를 모두 만족하는 로그를 표시합니다. ID 입력 초기값은 `0x000~0x7FF`이며 `0x000~0x1FFFFFFF` 범위로 Standard와 Extended를 모두 지원합니다. 같은 ID만 보려면 시작·끝을 같게 입력합니다.
    -   **필터 취소**: 진행 중인 필터를 중단하거나 적용된 필터를 해제하고 전체 버스·ID의 로그를 다시 표시합니다. 입력한 버스·ID 조건은 유지합니다. 기존 작업을 끝까지 기다리거나 전체 ID를 다시 검사하지 않고, 숨긴 행만 복원합니다. 숨긴 행이 많으면 복원 시간은 필요하며 상태 표시줄에 진행 상황을 표시합니다. 필터 버튼을 다시 꺼도 같은 방식으로 해제됩니다.
    -   대용량 로그의 필터 적용·해제 중에도 창을 조작할 수 있으며, 하단 상태 표시줄에서 처리 진행과 결과 개수를 확인할 수 있습니다. 처리 중 범위를 바꾸거나 필터를 해제하면 새 조건으로 다시 적용합니다. 저장·전송·복사는 필터가 완료된 뒤 사용할 수 있습니다.
    -   **Save**: 현재 필터 결과를 별도 `.trc` 파일로 저장합니다. 원본 헤더·시간·타입·방향·데이터·줄바꿈은 유지하고 메시지 번호만 1부터 다시 매깁니다. 원본과 다른 파일명을 사용해야 합니다. 필터가 꺼져 있으면 전체 표시 로그를 저장합니다.
    -   **로그 데이터 재전송**:
        -   **전송** 버튼: 현재 필터 결과만 원래 시간 간격으로 재전송합니다. 표시된 선택 행이 있으면 그 위치부터 시작하며, 없으면 첫 결과부터 시작합니다. 송신을 시작하면 대상 목록이 고정됩니다.
        -   **선택 전송** (또는 스페이스바): 표에서 선택한 한 줄의 데이터만 1회 전송합니다.
        -   **반복** 체크박스: 전송이 끝나면 필터 결과의 처음부터 다시 반복합니다.
        -   전송에 성공한 프레임은 원본 로그의 **TX/RX 구분과 관계없이**, 실제 전송한 **BUS·CAN ID**에 연결된 유저 패널 수신 도구에도 표시됩니다. 패널을 **STANDARD 또는 RUN**으로 두면 값·Enum·색상·그리드가 갱신됩니다. 드라이버의 송신 에코 없이도 표시하며, 수신 스레드나 메인 트리의 갱신에 의존하지 않습니다. 빠른 재생은 약 50ms 단위로 메시지별 최신 값을 표시합니다. EDIT는 기존 편집/표시 테스트 동작을 유지합니다.
        -   이 화면 갱신은 시퀀스의 응답 수신 판정과 구분합니다. RCV 대기는 실제 수신 프레임으로만 판정합니다.

## 6. 사용자 패널 (User Panel)

Tx Panel 툴바의 **User Panel** 버튼으로 여는 사용자 정의 조작/표시 화면입니다.

### 제어 모드
- **EDIT**: 도구 생성/삭제/배치/설정 변경 모드
- **STANDARD**: 유저 패널 TX 전체 정지, RX 표시 위젯 갱신 모드
- **RUN**: TX/RX 모두 동작
- Tool List, 속성 편집 공간, 페이지 추가/이름 변경/삭제 버튼은 EDIT에서만 보입니다. 페이지 탭과 작업 캔버스는 다른 모드에서도 사용할 수 있습니다.
- 편집 보안이 활성화된 경우(STANDARD/RUN -> EDIT 복귀 시) 비밀번호 입력이 필요합니다.
- 패널 닫기 또는 모드 변경 시 패널의 주기 송신·시퀀스·응답 대기·지연을 모두 중지합니다. RUN 진입 시 등록 패킷의 주기 전송은 첫 조작 없이 시작하며, 시퀀스는 실행 버튼으로 시작합니다. 메인 TX 패널의 별도 송신은 이 중지 범위에 포함되지 않습니다.
- RUN Init 시퀀스 영역은 캔버스 위에 표시됩니다. 캔버스와 Init 사이의 세로 splitter 손잡이로 높이를 조절하거나 접을 수 있으며, RUN을 벗어나면 숨겨집니다.
- 전역 Force RUN 모드는 없습니다. 일반 시퀀스 도구의 **강제 실행** 버튼은 RCV만 건너뛰고 CMD/DEL/START/STOP을 수행합니다(통신 인증 불필요). **패킷 제어** 버튼은 CMD/RCV를 제외하고 START/STOP/DEL만 실행합니다.

### TX 패킷 등록
- EDIT 모드의 **TX 패킷 등록 / 관리**에서 메인창과 같은 패킷 생성창으로 등록·수정·삭제합니다. 카운트 업/다운/순환, CRC-8/CRC-16 및 Hyundai CRC 설정을 지원합니다.
- DBC 신호별 카운터에는 기존 **None / 업 / 다운 / 왕복** 외에 **수신값 동기화 + 업/다운/왕복**을 선택할 수 있습니다. 송신 패킷과 같은 BUS/CAN ID의 최근 RX 프레임에서 해당 DBC 신호의 raw값을 읽습니다. RX값이 변경되면 그 값을 다음 TX에 우선 반영하고, 같은 값이 반복되거나 아직 수신값이 없으면 선택한 방향으로 min/max 범위에서 카운트합니다. CRC 설정이 있으면 카운터 반영 뒤 CRC를 계산합니다. 다른 CAN ID의 신호를 source로 지정하는 기능은 제공하지 않습니다.
- **딜레이 입력은 필수**입니다. `0`은 도구 값이 바뀔 때만 전송하며, 양수는 해당 ms마다 패킷을 전송합니다. 주기 패킷은 연결된 도구가 없어도 RUN에서 전송합니다.
- 양수 주기의 등록 패킷은 메인 TX와 동일한 스케줄러를 사용하는 BUS별 송신 스레드에서 전송합니다. 송신이 밀려 주기를 놓치면 밀린 프레임을 한꺼번에 보내지 않고, 원래 목표 시각을 기준으로 다음 주기로 건너뜁니다. 누락 주기와 최대 지연은 시스템 로그의 `TX 주기 지연` 경고로 확인합니다. 운영체제/드라이버의 실시간 성능을 보장하는 것은 아니므로 실제 장비에서 주기를 검증하세요.
- 같은 BUS·ID는 한 번만 등록합니다. 연결된 도구가 있는 패킷을 삭제하려면 먼저 도구를 삭제하거나 다른 등록 패킷에 연결합니다.
- 전송 데이터 적용 순서: **등록 원본 → 도구 신호의 지정 비트 덮어쓰기 → 활성 카운트 → 활성 CRC**. 도구가 지정하지 않은 비트는 원본을 유지합니다.
- 등록 목록은 패널 JSON 및 패키지에 저장됩니다. 파일을 불러오면 EDIT에서 시작합니다. 기존 파일의 미등록 TX 도구는 패킷 등록과 연결을 완료해야 RUN을 사용할 수 있습니다. RX 도구는 기존 DBC 전체 선택 방식을 유지합니다.
- 카운트/신호 CRC를 사용하는 패킷은 해당 DBC/SYM이 필요합니다.

### 도구 생성
- **Add TX Tool**: 등록한 패킷의 ID/심볼로 송신 위젯 생성
- **Add RX Tool**: 수신 위젯 생성
- **Add Group/Shape**: 그룹/탭/도형 도구 생성
- 도형 빠른 생성: **Draw Rect / Draw Line**

### 도구 복사·잘라내기
- EDIT에서 도구 하나 또는 Ctrl+클릭으로 여러 도구를 선택한 뒤 **Ctrl+C → Ctrl+V**로 복제합니다. 캔버스와 도구 목록에서 사용할 수 있으며, 복제본은 조금 이동한 위치에 선택됩니다.
- **Ctrl을 누른 채 선택 도구의 프레임/제목을 드래그**하면 선택된 도구들을 복사합니다. 이동 없이 Ctrl+클릭만 하면 기존처럼 선택/해제합니다.
- 그룹을 복사하면 하위 도구도 함께 복사합니다. 배치 간격·신호·스타일·시퀀스 설정은 유지하고, 복제본은 새로운 ID와 독립된 설정을 가집니다. Ctrl+Z/Y로 복제 작업을 취소/복원할 수 있습니다.
- **Ctrl+X → Ctrl+V**로 선택 도구를 잘라내고 붙여넣습니다. 그룹 하나를 선택해도 중첩 그룹·탭의 모든 하위 도구를 함께 옮기며, 이름·설정·내부 배치를 유지합니다. 대상 전체 탭으로 전환한 뒤 붙여넣을 수 있습니다. 잘라낸 항목은 한 번 붙여넣으면 클립보드에서 비우며, 잘라내기와 붙여넣기를 각각 Ctrl+Z/Y로 취소/복원할 수 있습니다.
- **Edit** 메뉴와 도구 목록의 우클릭 메뉴에서도 **Cut / Copy / Paste**를 사용할 수 있습니다. 속성 입력란의 Ctrl+X/C/V는 텍스트 편집에 사용합니다.
- 복사 후 속성에서 비슷한 신호로 변경할 수 있습니다. 다른 BUS에 같은 TX 도구를 만들려면 해당 BUS의 패킷을 먼저 등록하고, 복제본의 속성에서 BUS/등록 패킷을 선택합니다. 여러 복제본은 공통 속성의 **TX 등록 패킷**으로 한 번에 변경할 수 있습니다. RX는 기존 BUS·DBC 신호 선택을 사용합니다.

### TX 동작
- **button**: 누르면 `Button Push Value`, 떼면 `Button Pull Value`를 패킷의 지정 비트에 반영합니다. 전송 간격은 등록 패킷의 딜레이를 따릅니다.
- **toggle**: ON/OFF에 따라 `Toggle ON/OFF Value` 송신
- 같은 버스·CAN ID·비트 영역에 연결한 토글은 하나를 켜면 나머지가 해제됩니다. 자동 해제된 토글의 OFF 값은 송신하지 않습니다. 켜진 토글을 다시 클릭하면 자신의 OFF 값을 송신합니다.
- **slider/spinbox**: `Min/Max/Resolution` 기반 값 송신
- **slider**: 정수형 신호(정수 scale/offset) 또는 정수 Resolution은 정수로 표시합니다. 나머지는 Resolution 자릿수에 맞춰 `0.1 → 1.0`, `0.01 → 1.00`처럼 표시합니다. `Initial Value (Home)`는 초기 위치이며, 왼쪽 Home 버튼은 슬라이더·값 표시의 두 행을 차지합니다. RUN에서 Home을 누르면 해당 값도 송신합니다. 초기 위치는 범위와 이동 단계에 맞춰 적용됩니다. 슬라이더에 Tab 또는 클릭으로 포커스를 두면 좌/우 방향키로 한 단계씩 감소/증가합니다. 아래 입력란에 숫자를 입력하고 **Set** 또는 Enter를 누르면 해당 위치로 이동합니다. 범위 밖 숫자는 최솟값/최댓값으로 제한하고 이동 단계에 맞춥니다. 빈 입력·문자·NaN·무한대 등 유효하지 않은 값은 Home으로 복귀합니다. RUN의 Tx 슬라이더는 이 조작에도 기존 송신 방식을 적용합니다.
- **프레임 형식·길이·BRS·딜레이**는 등록 패킷에서 설정합니다. 도구별 TX Cycle Mode / TX Cycle 입력은 제거되었습니다.
- 단일 속성은 등록 패킷과 신호/비트 필드를 선택합니다. 멀티 공통 속성의 **TX 등록 패킷**으로 연결을 일괄 변경할 수 있습니다. RX BUS와 공통 배치·크기·BUS 속도 변경은 유지됩니다.

### 명령 시퀀스

**RUN Init 시퀀스 설정**에서 RUN 진입 시 자동 실행할 순서를 등록합니다. Init은 `CMD` 송신, `DEL` 대기, `START` 주기 시작, `STOP` 주기 정지만 지원하며 수신 비교는 없습니다. 목록을 비우면 Init을 사용하지 않습니다.

- RUN 진입 → Init 실행 → 성공 후 등록 주기 전송 시작 순서입니다. Init이 없으면 바로 등록 주기 전송을 시작합니다.
- Init 동안 일반 TX 도구/시퀀스 조작과 자동 주기 전송을 보류합니다. Init의 CMD는 실행되며, START/STOP으로 정한 주기 전송 상태는 Init 완료 후 적용됩니다.
- Init에서 STOP한 패킷은 자동으로 재시작하지 않습니다. 일반 시퀀스의 START로 다시 시작할 수 있습니다. Init 실패/중단 시 STANDARD로 돌아갑니다.
- RUN에 다시 진입하면 Init을 처음부터 실행합니다. Init과 실패 처리 설정은 패널 JSON/패키지에 함께 저장됩니다.

`Add TX Tool → sequence → 명령 시퀀스 설정`에서 생성합니다. 버튼과 로그를 보려면 Row Span 8, Col Span 12 정도의 영역을 권장합니다.

- 그리드 열: 종류(CMD/RCV/DEL/START/STOP), 패킷 생성/편집 또는 대상 선택, 명령어/응답 이름, 읽기 전용 요약 또는 비트 편집 버튼.
- 생성은 선택 행 아래에 삽입합니다. 삭제 및 위로/아래로 버튼으로 단계를 관리합니다.
- CMD: 등록한 TX 패킷을 선택하고 반복 횟수를 지정합니다. 도구 값과 카운트·CRC를 반영하는 공통 전송 처리를 사용하며, 반복 간격은 등록 패킷 딜레이를 따릅니다.
- CMD의 **패킷 생성 / 편집 → CMD 전용 값 사용**을 체크하면 `Data (HEX)` 또는 `DBC Signals → Value`에서 해당 단계의 송신값을 편집할 수 있습니다. Init·일반 시퀀스·실패 처리에서 공통으로 지원합니다. 카운트와 CRC 적용 후 송신에 성공한 데이터가 현재 패킷 값이 되어 이후 주기 전송에도 유지됩니다. 송신 실패 시에는 이전 값을 유지합니다.
- 시퀀스 종료와 STANDARD→RUN 전환으로 현재 값을 초기화하지 않습니다. 다음 시퀀스 CMD로 초기값을 보내면 그 값으로 갱신됩니다. 도구 조작은 해당 비트만 변경하며, 활성 카운트/CRC는 매 전송마다 계속 계산합니다. 등록 원본은 변경하지 않습니다.
- `CMD 전용 값 사용`을 해제하면 현재 패킷 값을 사용합니다. BUS/ID/길이/주기/카운트·CRC 설정은 등록 패킷에서 변경하며, 등록 길이가 바뀌면 CMD 전용 데이터 길이도 다시 맞춰야 합니다.
- RCV: 동일 ID의 신호를 하나 이상 체크하여 기대값을 설정하거나, DBC 없이 `[0]: XXXX XX01` 비트를 편집합니다. `X`는 비교 제외이며, 같은 프레임에서 모든 비교 비트와 버스·ID·형식·길이가 일치해야 합니다. 제한 시간(ms)을 넘기면 중단합니다.
- DEL: 설정 시간(ms) 후 다음 단계로 이동합니다.
- START/STOP: 등록 패킷 개별 또는 전체의 **자동 주기 전송**을 시작/정지합니다. 같은 패킷의 CMD 송신과 딜레이 0 도구의 값 변경 송신은 유지됩니다. START를 반복해도 타이머가 중복 생성되지 않습니다.
- 일반 시퀀스는 수신 조건 일치 시 OK, 수신 타임아웃/송신 오류 등 발생 시 NG로 표시합니다. 불일치 프레임은 제한 시간 동안 계속 기다립니다.
- **실패 시 실행할 명령 설정**에 CMD/DEL/START/STOP 목록을 입력할 수 있습니다. 실패하면 정상 단계 진행을 중단하고 해당 목록을 한 번 실행합니다. 실패 처리에 성공해도 원래 시퀀스 결과는 NG이며, 실패 처리 자체가 실패하면 즉시 종료합니다.
- 사용자의 정지, STANDARD/EDIT 전환, 패널 닫기는 실패 처리 목록을 실행하지 않고 모든 시퀀스 동작을 취소합니다.
- CMD는 등록 패킷을 참조합니다. RCV는 기대 바이트와 비교 마스크로 저장하며 기존 `X/0/1` 편집을 유지합니다.
- 일반 실행과 강제 실행 버튼은 실행 → 정지 → 처음부터 재실행입니다. 강제 실행은 RCV를 무시하고 나머지 CMD/DEL/START/STOP을 진행합니다. 패킷 제어 버튼은 CMD/RCV를 건너뛰고 START/STOP/DEL만 수행합니다. 일반 로그는 검정, 오류는 빨강, 전체 완료는 녹색입니다. 시퀀스 로그 글꼴은 화면 공간을 위해 축소되어 표시됩니다.
- 로그에는 패킷 바이트 대신 이름을 표시합니다. ID는 Standard 3자리, Extended 8자리입니다.

```text
[10:30:00.001] 1/3 CMD BUS_1 0x001 Init 명령 · 송신 완료
[10:30:00.125] 2/3 RCV BUS_1 0x00000001 Init 응답 · 응답 조건 일치
[10:30:00.126] 3/3 DEL - - 안정화 대기 · 200 ms 대기
```

상세 실행 규칙은 [시퀀스 사용법](USER_PANEL_SEQUENCE.md)을 참고하세요.

### RX 동작
- **progress / label / status_lamp / grid_view** 위젯 지원
- **grid_view**: **Add RX Tool → grid_view → DBC 트리에서 신호 선택…**으로 생성합니다. 심볼 체크는 하위 신호 전체를, 개별 신호 체크는 해당 항목만 선택합니다. 체크한 순서대로 행을 추가하며, 해제 후 다시 체크하면 마지막 행으로 이동합니다. 심볼을 한 번에 선택하면 아직 선택하지 않은 신호들을 DBC의 신호 순서대로 덧붙입니다.
- 그리드 속성에서 **버스 / 심볼명 / 신호명 / 사용자이름** 중 표시할 열을 체크합니다. **값은 항상 표시**합니다. 사용자이름은 DBC 트리 선택창의 해당 열을 더블클릭해 입력하며, 비우면 신호명을 표시합니다. 기존 패널은 버스·심볼명·신호명을 표시합니다.
- 생성·편집 시 글자 길이에 맞춰 열 너비를 계산하고 남은 너비는 값 열에 배정합니다. 최소 도구 크기는 선택한 행 수·표시 열·글자 길이로 계산하며, 확대하면 너비와 높이에 맞춰 글자도 커집니다. 그리드 전체 크기보다 내용이 크면 스크롤을 사용합니다.
- STANDARD/RUN에서 수신값·단위·열거값을 갱신하며, 신호 선택·행 순서·표시 열·사용자이름은 `.pjjupkg`에 저장됩니다. DBC에 없는 저장 항목은 선택 목록에서 확인·해제할 수 있습니다.
- **grid_view의 Enum**은 팩터·옵셋 적용 전 **RAW 값**으로 조회합니다. 매칭되면 `Enum 이름 (물리값 단위)`, 매칭되지 않으면 `RAW × Factor + Offset`으로 계산한 물리값과 단위를 표시합니다.
- **label**은 DBC의 Enum에 RAW 값이 매칭되면 Enum 이름을, 매칭되지 않으면 팩터·옵셋을 적용한 숫자를 표시합니다. 단위가 있으면 `Ready V`, `11.5 V`처럼 함께 표시합니다. 도구에 지정한 단위를 우선 사용하고, 없으면 DBC의 단위를 사용합니다.
- 그리드 제목 오른쪽의 **그래프 아이콘**은 표시 중인 모든 신호를 행 순서대로 메인창과 같은 실시간 그래프 창에 엽니다. 그래프의 동기화·Combined View·세션 저장 기능도 동일하게 사용할 수 있습니다.
- **progress**: 속성의 **Progress 표시**에서 `퍼센트`, `실제 값`, `퍼센트 + 실제 값`을 선택합니다. 퍼센트는 Min~Max 기준 0~100%, 실제 값은 스케일·오프셋과 단위를 반영한 수신값입니다. 표시 선택은 패널 패키지에 저장되며, 기존 패널은 퍼센트 표시를 유지합니다.
- **status_lamp**: ON/OFF 조건을 독립 설정
- 조건 연산자: `gt`, `ge`, `lt`, `le`, `eq`, `ne`, `between`, `outside`

- **Apply All RX**: 모든 RX 도구에 동일 값 주입

### 배치/그룹 편집
- **Tool List**에서 선택/우클릭(Edit/Delete/Z-order)
- **Bring Front / Send Back / Forward / Backward**: 전후 배치 순서 변경
- 도구 프레임 드래그로 이동, 우하단 드래그로 크기(span) 변경
- 오른쪽 **Tool Properties**: 도구를 선택하거나 **Edit**를 누르면 별도 창 없이 위치·크기·CAN·DBC·신호·값/동작을 편집합니다. 수정 후 **Apply Properties**를 누릅니다. 다른 도구를 선택하기 전에 적용해야 합니다.
- 도구 설정은 **기본 / CAN·DBC / 값·동작 / 색상·조건 / 그리드** 탭에 나눠 표시하며, 해당 도구에 필요한 탭만 보입니다. 일반 설정은 행마다 같은 배경색을 사용하는 **항목 / 설정값** 표에서 편집합니다. 우측 **창으로 보기…**는 입력 중인 값을 가져와 넓은 별도 창을 엽니다. OK로 도구에 적용하고, Cancel은 미확정 색상 미리보기를 되돌립니다. 그 외 우측 입력 중인 속성은 유지합니다. 한 개 도구를 선택한 EDIT 모드에서 사용할 수 있습니다.
- 생성은 기존 설정창을 사용합니다. 시퀀스의 단계·패킷·비트 상세 편집은 속성창 내부에서 열리며, 상세 편집의 OK 후 **Apply Properties**로 도구에 반영합니다.
- Tool List에서 **Ctrl+클릭 / Shift+클릭**, 캔버스의 프레임·제목에서 **Ctrl+클릭**으로 여러 도구를 선택합니다. 다른 값은 `(Mixed)`로 표시됩니다.
- 다중 선택에서는 변경할 항목만 체크하고 **Apply Checked Properties**를 누릅니다. 위치·크기·CAN BUS·일반 도구의 TX 주기/프레임 형식/BRS를 일괄 적용하며, 체크하지 않은 항목은 유지합니다. 시퀀스의 CAN BUS 변경은 포함된 CMD/RCV 패킷에 적용됩니다.
- **CAN BUS Speed**에서 nominal bitrate와 FD data bitrate를 변경할 수 있습니다. 속도는 같은 BUS의 모든 도구가 공유하며, 해당 BUS를 연결 해제한 뒤 적용해야 합니다. 메인창의 연결 속도 설정에도 반영됩니다. 패널 파일의 저장 속도는 불러오기만으로 장비에 적용하지 않으며, 체크 후 적용합니다.
- 그룹/탭 위로 드롭하면 자동으로 해당 부모에 편입됩니다. 이동 전의 도구 크기를 유지하며, 내부 공간이 부족하면 스크롤로 볼 수 있습니다.
- 그룹(`group_box`)·탭(`tab_container`)·사각형(`shape_rect`)은 **색상 / 스타일 설정**에서 배경색과 테두리 색상·두께·스타일·모서리를 설정합니다. 선(`shape_line`)은 선 색상·두께·스타일을 설정합니다. **색상 선택** 버튼을 눌러 추천 색상 10개 또는 색상표 48개를 클릭하거나 **사용자 지정 색상…**을 선택합니다. 배경색 선택 시 채우기가 자동으로 켜지며, **배경색 채우기**를 해제하면 채우기를 끕니다. 속성 편집 후 **Apply Properties**로 반영합니다. 그룹/탭 내부 배경에도 색이 적용되며, 하위 도구는 각각의 색상을 유지합니다.
- 추천색은 색상 견본과 **색 파란색**처럼 이름으로 표시하며, 그 외 색상만 **색 #XXXXXX**로 표시합니다. HEX 값은 툴팁에서도 확인할 수 있습니다.
- 우측 또는 **창으로 보기…**에서 기존 도구의 색상·스타일을 바꾸면 화면에 즉시 미리보기로 표시합니다. **Apply Properties / OK**에서만 확정하며, 다른 도구 선택·편집 영역 밖 클릭/단축키·모드 전환·도구 갱신·닫기 시 미확정 색상을 되돌립니다. 미리보기는 파일/자동 저장 및 실행 취소 이력에 포함하지 않습니다. 설정 내부의 색상표·사용자 지정 창·탭 이동은 편집을 계속할 수 있습니다.
- 최상위 캔버스와 그룹/탭 내부는 같은 격자 칸 크기를 사용합니다. 창을 넓히면 배치할 수 있는 칸 수가 늘어나며, 기존 도구의 크기는 유지됩니다.
- 일반 도구의 기본·최소 크기는 **Row Span 3 × Col Span 6**입니다. 기존 패널의 더 작은 도구도 불러올 때 이 크기로 보정합니다. 슬라이더·시퀀스의 더 큰 최소 크기는 유지하며, 선 도형은 두께 유지를 위해 1을 허용합니다.

### 수신 라벨의 조건별 색상

- RX `label` 도구를 선택한 뒤 **색상 / 조건 → 색상 규칙 표 편집…**을 엽니다. 표의 한 행이 한 규칙이며, **사용 / 기준 / 조건 / 값·min·Enum / max / 적용 대상 / 색상** 열에서 설정합니다. 행이 많아지면 표 내부를 스크롤하므로 설정창이 길어지지 않습니다.
- 신호에 Enum이 있으면 **Enum** 또는 **물리값**을 선택합니다. **Enum 일괄 추가**는 현재 신호의 Enum을 각각 한 행으로 추가하며, 이후 행마다 색상을 바꿀 수 있습니다. Enum이 없는 신호는 물리값 조건을 사용합니다.
- Enum 조건은 DBC의 **RAW 값**과 비교합니다. 물리값 조건은 **Scale·Offset이 적용된 값**과 비교합니다. DBC를 찾지 못해도 저장된 Enum RAW 규칙은 보존하며, 저장된 비트·Scale·Offset 설정에 따라 적용합니다.
- 비교 조건은 **작을 때 / 작거나 같을 때 / 같을 때 / 다를 때 / 클 때 / 크거나 같을 때 / 범위 안 / 범위 밖**입니다. 단일 비교에는 첫 값만 사용합니다. 범위 비교에는 첫 값(min)과 max를 입력하며 min ≤ max여야 합니다. 범위 안은 **min ≤ 값 ≤ max**, 범위 밖은 **값 < min 또는 값 > max**입니다.
- 적용 대상은 **배경색** 또는 **글자색**입니다. 색상 버튼에서 기존 **추천 10색 / 색상표 48색 / 사용자 지정 색상**을 선택합니다. 배경색만 지정하면 글자색은 밝기에 따라 자동 조절합니다.
- 여러 행이 일치하면 **위쪽부터 배경색·글자색 각각 첫 일치**를 적용합니다. **위로 / 아래로**로 우선순위를 바꾸고, 체크를 끄면 해당 행을 제외합니다. 일치하지 않는 대상은 기본 색상으로 돌아갑니다.
- 규칙 표의 OK는 입력 중인 도구 설정에 반영합니다. 마지막으로 **Apply Properties**(우측) 또는 **OK**(설정창)를 눌러 적용합니다. 적용한 규칙은 패널·통합 설정에 저장하며 실행 취소·다시 실행을 지원합니다. EDIT의 **표시 테스트**에서도 확인할 수 있습니다.
- 규칙 표에서 색을 바꾸는 동안 현재 수신값 또는 **표시 테스트** 값에 맞는 색을 즉시 미리봅니다. 규칙 표를 Cancel하면 표를 열기 전 색으로 돌아가고, 최종 Apply 전에 다른 작업으로 넘어가면 마지막 확정 색으로 돌아갑니다.

### 실행 취소 / 다시 실행

- EDIT 모드에서 **Ctrl+Z**로 실행 취소, **Ctrl+Y**로 다시 실행합니다. Edit 메뉴의 Undo/Redo에도 현재 가능한 횟수가 표시됩니다.
- 생성·삭제·위치·크기·전후 순서·적용한 도구 속성(시퀀스 설정 포함)을 최대 **50단계** 보관합니다. 다중 삭제와 속성 일괄 적용은 각각 한 단계이며, 생성창의 미리보기는 생성 확정 시 한 단계로 묶습니다.
- 실행 취소 후 새 작업을 적용하면 다시 실행 이력은 지워집니다. 패널 파일을 불러오거나 창을 닫으면 이력이 초기화되며, 파일에 이력은 저장하지 않습니다.
- CAN 송신·수신, 장비 연결 상태, BUS 실제 통신 속도는 되돌리지 않습니다. 통신 속도는 CAN BUS Speed에서 별도로 변경합니다.
- 속성 입력란에서 Ctrl+Z는 입력 중인 글자를 되돌립니다. 패널 작업을 되돌리려면 캔버스/도구 목록에 포커스를 두거나 Edit 메뉴를 사용합니다.

### 충돌 점검
- **Check TX Overlap**: 동일 CAN 프레임의 비트 오버랩 점검
- 오버랩 도구는 Tool List에서 빨간색으로 표시
- **Focus Conflict** 또는 항목 더블클릭으로 충돌 도구 간 이동

### 저장/불러오기
- **File → Save Panel**: 패널 설정과 BUS별 DBC/SYM을 하나의 `.pjjupkg` 파일로 저장합니다. 확장자를 생략하면 `.pjjupkg`를 붙입니다.
- **File → Load Panel**: `.pjjupkg` 파일을 선택해 패널과 포함된 DB를 함께 복원합니다. 불러온 뒤에는 STANDARD/대기 상태가 됩니다.
- **Save**에 시퀀스 순서·이름·패킷·비교 마스크·타임아웃·지연·반복 설정도 포함됩니다. 로그와 실행 진행 상태는 저장하지 않습니다.
- 패널 패키지 저장: `*.pjjupkg`
  - 패널 도구 설정 + Bus별 DB 파일(dbc/sym) 묶음 저장
  - 패키지 로드 시 기존 DB 목록을 교체 후 패널 복원
- 사용자 저장·불러오기 형식은 `.pjjupkg`로 통일했습니다. 패키지 파일 하나를 옮기면 다른 PC에서도 패널과 DBC/SYM을 함께 사용할 수 있습니다.

### 도구 배치 페이지 탭

- 편집 모드에서 배치 공간 위의 **+ 탭**을 눌러 이름을 입력하면 새 페이지가 생성됩니다. **탭 이름 변경** 버튼 또는 탭 이름 더블클릭으로 이름을 바꿀 수 있습니다.
- **탭 삭제** 버튼은 현재 페이지와 포함된 모든 도구를 확인 후 삭제합니다. 마지막 페이지는 삭제할 수 없으며, Ctrl+Z로 페이지와 도구를 함께 복원할 수 있습니다.
- 새 도구는 현재 탭에 배치됩니다. 도구 목록과 그룹 부모 선택도 현재 탭을 기준으로 표시됩니다. 다른 탭으로 같은 도구를 복사하려면 Ctrl+C 후 대상 탭에서 Ctrl+V를 누릅니다.
- 탭 전환은 도구 값이나 진행 중인 시퀀스를 초기화하지 않습니다. RUN의 등록 패킷 전송과 수신 처리는 표시 중인 탭과 무관하게 유지됩니다. RUN/Standard에서는 탭을 전환할 수 있지만 추가·이름 변경·삭제는 편집 모드에서만 가능합니다.
- 탭 이름·소속 도구·선택 탭은 JSON 및 패널 패키지에 함께 저장됩니다. 탭 정보가 없는 기존 패널 파일은 모든 도구를 **페이지 1**에 배치하여 불러옵니다. 탭 추가·이름 변경·삭제는 Undo/Redo를 지원합니다. 격자 크기, 등록 패킷, Init 시퀀스는 패널 전체에서 공유합니다.

### 도구 내부의 탭 설정

- **Add Group/Shape → tab_container**로 탭 도구를 생성합니다. 생성 창 또는 선택한 도구의 속성에 있는 **탭 설정**에서 탭 추가·이름 변경·삭제를 편집한 뒤 **OK / Apply Properties**로 적용합니다. 목록의 탭 이름을 더블클릭해도 이름을 변경할 수 있습니다.
- 내부 탭은 최소 한 개를 유지합니다. 탭 삭제 시 안의 도구는 다음 탭으로 이동하며, 마지막 탭을 삭제하면 이전 탭으로 이동합니다. 다른 탭의 도구는 원래 탭에 남습니다. 적용한 변경은 Undo/Redo와 저장/불러오기를 지원합니다.
- 자식 도구의 **Parent Group/Tab**에서 탭 도구를 선택한 뒤 **배치할 탭**을 지정할 수 있습니다. 드래그로 넣을 때는 현재 표시 중인 내부 탭에 배치됩니다.

### DBC 없이 신호 편집

- Init/일반/실패 처리 시퀀스의 CMD에서 **CMD 전용 값 사용 → 직접 HEX / BIN / X 입력**을 켜면 신호 선택 없이 원시 값을 입력할 수 있습니다. RCV에서도 **직접 HEX / BIN / X 입력**으로 비교 값을 지정합니다.
- HEX 예: `01 02 03 04 05 06 XX 08`, BIN 예: `0010 0001 1100 XXXX`. 왼쪽부터 첫 바이트이며 BIN은 상위 비트부터 입력합니다. HEX의 X 하나는 4비트, BIN의 X 하나는 1비트입니다. 바이트 단위로 입력하며 생략한 뒤쪽 바이트도 X로 처리합니다.
- CMD의 X는 등록 패킷의 현재 비트를 유지합니다. 지정한 비트를 덮어쓴 후 활성 카운트·CRC를 적용하고, 송신 성공한 최종 값을 유지합니다. RCV의 X는 비교에서 제외합니다. RCV 전체가 X이면 등록할 수 없습니다.
- **수신 DLC 차이 허용**은 기본 해제입니다. 켜면 DLC 8 설정에서 비교 값이 `11 22` 또는 `11 22 XX XX`일 때 실제 수신 `11 22 CC FF`도 OK입니다. 비교 대상으로 지정한 바이트가 실제 수신에 없으면 통과하지 않으며, BUS·ID·Standard/Extended·FD·BRS 조건은 계속 검사합니다.
- 직접 입력 값과 비트 마스크, 입력 형식, DLC 차이 허용 설정을 패널에 저장합니다. 이 원시 값 송신·비교에는 DBC가 필요하지 않습니다.

- Start Bit, Bit Length, Byte Order, Scale, Offset, Signed 설정을 패널에 저장합니다. DBC가 없어도 이 정보를 사용해 값을 송수신합니다. Intel(little-endian)과 Motorola(big-endian)의 정수 신호를 지원합니다.
- DBC Message/Signal을 선택하면 Start Bit와 Length 등을 자동으로 입력합니다. 두 항목은 DBC를 사용하는 동안에도 표시하고 수정할 수 있습니다.
- 저장된 비트 정보와 현재 BUS·CAN ID·Byte Order에 맞는 신호가 있으면 DBC 신호를 연결합니다. DBC가 없거나 변경되어 일치하지 않으면 **Unknown (Manual)**로 표시하고 저장된 비트 정보는 유지합니다.
- Start Bit/Length를 직접 수정하면 신호를 다시 매칭합니다. 같은 위치를 공유하는 신호가 여러 개이고 기존 선택으로 구별할 수 없으면 Unknown으로 표시하며, 원하는 신호를 직접 선택할 수 있습니다.
- 패킷 길이를 벗어나는 비트 범위, 잘못된 CAN ID/프레임 길이, Scale 0은 적용하지 않습니다.

## 7. 실행·빌드 및 버전

버전은 `build_exe.py`의 `APP_VERSION = "R012_1"`로 지정합니다.

- 소스 실행: 의존성 설치 및 가상환경 활성화 후 `python main.py`. 버전 변경은 재실행 시 반영됩니다.
- 빌드: 같은 환경에서 `python build_exe.py`.
- Windows 실행 파일: `dist/PCAN_Viewer_JJ_R012_1_win/PCAN_Viewer_JJ_R012_1_win.exe`.
- Linux 바이너리: `dist/PCAN_Viewer_JJ_R012_1_linux/PCAN_Viewer_JJ_R012_1_linux`.
- 제목은 실행 파일명에서 버전을 읽습니다. 소스 수정 후 기존 실행 파일은 바뀌지 않으므로 R012_1를 다시 빌드해야 합니다.
- 배포 폴더에 사용자 매뉴얼·시퀀스 사용법·변경 내역·OS별 실행 안내가 함께 복사됩니다.
- 기본 글꼴은 Consolas입니다. 설치되지 않은 환경과 지원하지 않는 한글 등은 시스템 대체 글꼴이 표시될 수 있습니다.
- Linux 세션은 이전 연결 상태와 관계없이 BUS를 Close로 시작합니다. 개발 테스트는 Python 3.13에서 `python -B -m unittest discover -s tests`로 실행하며, 실제 CAN 장비와 OS별 빌드 결과는 별도 검증해야 합니다.

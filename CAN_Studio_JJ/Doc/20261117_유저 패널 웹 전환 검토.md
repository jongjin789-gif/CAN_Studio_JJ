## 1. 요청 사항

### 1.1 기본 요구

| 번호 | 요구 |
|---|---|
| Q1 | 메인 모니터링, 그래프, 로그 보기는 그대로 두고 **유저 패널만 웹 방식으로 전환** |
| Q2 | 웹 패널의 통신 패킷 송수신 방식 구상 |
| Q3 | 기존처럼 **송신 패킷 등록**이 필요 |
| Q4 | 선택에 따라 **INIT** 사용. INIT에서 패킷별 **전송 On/Off**와 **전송 주기 변경** 가능 |
| Q5 | 기존 송신/수신 도구의 기능을 그대로 사용 (단독, 멀티, 시퀀스 등) |
| Q6 | 기존보다 **도구 종류 확대** |
| Q7 | 가능하면 **이벤트(조건)에 따른 색상 설정** |

### 1.2 가장 원하는 기능: AI 생성

| 번호 | 요구 |
|---|---|
| A1 | DBC에서 사용할 송수신 패킷과 신호를 알려주고 **"어떤 컨셉"(계기판, 차량 등)으로 이미지형 패널 생성** |
| A2 | 생성된 화면에서 **송신 패킷의 세부 설정(카운터, CRC, 주기, 값 등)은 사용자가 직접 입력** |
| A3 | 이미지 없이 **탭/패널로 그룹화**하고 램프, 라디오 버튼, 프로그레스 바 등으로 **신호 상태를 한눈에** 보는 화면 생성 요청 |
| A4 | 위 기능에 필요한 **세부 항목 규칙** 정리 |

### 1.3 검토 중 확인된 전제

- 배포용 앱이므로 **AI 생성이 VS Code 같은 개발 환경에 묶이면 안 됨**.
- 공유 패킷(같은 BUS/CAN ID를 여러 도구가 함께 쓰는 구조)은 **신호 값 동기화를 위한 의도된 구조**이며 유지함.
- 패널 전용 앱(메인창 숨김)으로 쓸 때 운용자는 CRC 같은 세부값을 다루지 않음.

## 3. 목표 구조

### 3.1 원칙

**엔진은 Python에 그대로 두고, 화면만 웹으로 바꿉니다.**

```
[Python 엔진: 기존 유지]                        [웹 화면: 신규]
 python-can, DBC 디코딩                          도구 렌더링 (HTML/CSS/SVG)
 등록 패킷, 주기 송신 스레드        ◀── 브리지 ──▶  편집기, 속성창, 탭/패널
 카운터, CRC, 시퀀스, INIT 엔진                   이벤트 색상, 계기판 부품
 모드 보안, 검증, 저장/로드                        AI 생성 창
```

- 웹은 "값 변경", "START/STOP", "시퀀스 실행" 같은 **요청만 보냅니다**. 실제 송신 시점은 엔진이 정합니다.
- 엔진은 신호 최신값을 **묶음(스냅샷)** 으로 웹에 보냅니다.

### 3.2 웹을 띄우는 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| A. 앱 내장 | `QWebEngineView` + `QWebChannel` | **권장.** 단일 exe 유지, 외부 노출 없음. exe 크기 약 100~150MB 증가 |
| B. 로컬 서버 + 브라우저 | 앱 안 WebSocket 서버 | 태블릿·다른 PC 접속 가능. 인증과 접근 제한 필수. 추후 옵션 |

### 3.3 송수신 흐름 (Q2)

```
송신: 웹 도구 조작 → 브리지 → 엔진: 공유 패킷 데이터에 신호 반영
      → 주기 송신 스레드(또는 즉시 송신) → 카운터 → CRC → CAN

수신: CAN → 수신 스레드 → DBC 디코딩 → 신호별 최신값 저장
      → 20~50ms 주기 스냅샷 → 브리지 → 웹 도구 갱신, 이벤트 색상 판정
```

## 4. 기능 유지 요구 대응 (Q3~Q5)

### 4.1 엔진 층: 기존 코드 재사용

| 기능 | 웹 전환 시 |
|---|---|
| 송신 패킷 등록, BUS별 주기 송신 | 그대로 |
| 카운터(up/down/왕복/rx 동기화), CRC | 그대로 |
| 단일 명령, 멀티 명령 | 그대로. 웹은 도구 조작만 전달 |
| 시퀀스(CMD/RCV/DEL/START/STOP, 실패 처리), Force, Packet Control | 그대로 |
| INIT 실행 | 그대로 + 아래 4.2 확장 |
| 모드 보안(EDIT/STANDARD/RUN) | 그대로 |
| 저장, 패키지, 자동 저장, DBC 일치 확인 | 그대로. 기존 v5 파일 열기 유지 |

### 4.2 INIT 확장 (Q4)

| 요구 | 현재 | 필요한 작업 |
|---|---|---|
| 패킷별 전송 On/Off | START/STOP 단계로 가능 | 웹에서 패킷 목록 + On/Off 스위치 형태로 편집 화면 제공 |
| 전송 주기 변경 | **불가** (등록 패킷의 cycle 고정) | 엔진에 주기 변경 단계 추가 필요. 예: `{"kind":"CYCLE","target_packet_id":"pkt-b1-123","cycle":100}` |

주기 변경을 INIT에서만 허용할지, 일반 시퀀스와 RUN 중 조작에서도 허용할지는 결정이 필요합니다(9절).

### 4.3 화면 층: 웹으로 재작성

13종 도구, TX 패킷 표(Ctrl+C/V 복제, 드래그 순서), INIT 편집기, 시퀀스 편집기, 도구 설정창, 색상 규칙, 아이콘 도구 모음, 상태줄, 시스템 로그, 실행 취소/다시 실행, 표시 테스트.

## 5. 도구 확대와 이벤트 색상 (Q6, Q7)

### 5.1 추가 도구 후보

| 분류 | 도구 |
|---|---|
| 송신 | 라디오 버튼(ENUM 선택), 기어 선택(P/R/N/D), 핸들(회전 입력), 페달(세로 막대 입력), 다이얼, 프리셋 버튼(값 묶음 적용) |
| 수신 | 원형 게이지, 세로/가로 막대, 7세그먼트 숫자, 다색 상태표, 경고등 아이콘, 미니 트렌드 그래프, 값 표 |
| 복합 | 입력/출력 한 줄 도구(송신값과 수신 응답 나란히), 차량 평면도(바퀴 각도, 제동등, 방향지시등) |
| 구성 | 탭 개수 무제한, 접이식 패널, 이미지 배경, 텍스트 메모 |

### 5.2 이벤트 색상

기존 RX 라벨 조건 색상 규칙을 **모든 도구 공통 규칙**으로 넓힙니다.

- 대상: 배경색, 글자색, 테두리, 아이콘 색, 깜빡임
- 조건: 작음, 이하, 같음, 다름, 초과, 이상, 범위 안, 범위 밖, ENUM 값, **수신 끊김(타임아웃)**
- 여러 규칙은 우선순위 순서로 판정하고 처음 맞는 규칙을 적용

## 6. AI 생성 기능 (A1~A3)

### 6.1 역할 분담

| 항목 | 담당 |
|---|---|
| 화면 배치, 탭·그룹 구성, 신호와 도구 연결 | AI (또는 템플릿) |
| BUS, CAN ID, 길이, 비트 위치, 스케일, 오프셋 | 앱이 로컬 DBC에서 자동 입력 |
| **카운터, CRC, 주기, 버튼 값, 슬라이더 범위, 초기값** | **사용자가 도구를 클릭해서 입력** |
| INIT, 시퀀스 단계 | 사용자 입력 (AI는 초안 제안까지만) |

AI가 송신 세부값을 추측하지 않고 **"미설정"으로 남기며**, 미설정 항목이 있으면 RUN을 막습니다.

### 6.2 생성 유형

| 유형 | 요청 예 | 결과 |
|---|---|---|
| 컨셉형 (A1) | "VehSpd, MotRpm, GearPos는 계기판, APS·브레이크 지령은 제어부로" | 게이지·핸들·차량 그림 + 제어부 |
| 상태 보기형 (A3) | "BMS 신호는 탭 1에 램프로, 모터 신호는 탭 2에 막대로 묶어줘" | 탭/패널 그룹, 램프·라디오·프로그레스 바 |

제어부는 이미지형보다 **버튼 + 탭 + 입력/출력 나란히** 배치가 가독성과 안전성 모두 유리합니다. 계기판은 이미지형, 제어부는 버튼형으로 섞는 구성을 권장합니다.

### 6.3 사용 흐름 (EDIT 모드)

```
[AI 생성] → 요청 입력 + 대상 DBC 선택
 → 확인 질문(모호할 때만)
 → 미리보기 (송신 없음, 시뮬레이션 값)
 → 적용 (실행 취소 가능)
 → ⚠ 미설정 목록에서 송신 세부값 입력
 → 기존 RUN 절차(INIT 포함)로 사용
```

### 6.4 AI가 동작하는 위치

AI는 앱 안에 들어가지 않습니다. 앱은 요청 전송, 결과 검증, 미리보기만 합니다.

| 방식 | 내용 | 판단 |
|---|---|---|
| 1. 회사 중계 서버 경유 API | 앱 → 사내 서버 → 외부 AI 서비스. 키는 서버에만 보관 | **권장 (완전 자동)** |
| 2. 복사/붙여넣기 | 앱이 요청문 생성 → 사용자가 허용된 웹 AI에 붙여넣기 → 결과를 앱에 붙여넣기 | 서버 없이 바로 사용 가능 (반자동) |
| 3. 템플릿 | 컨셉 선택 + 역할 지정, AI 없음 | 오프라인 현장용 |

세 방식을 모두 두고 연결 상태에 따라 고르게 합니다. AI를 바꿔도 결과물(패널 정의 JSON)의 형식은 같습니다.

## 7. 세부 항목 규칙 (A4)

### 7.1 통신 (R-COM)

| ID | 규칙 |
|---|---|
| R-COM-1 | 주기 송신, 시퀀스 딜레이, RCV 타임아웃은 **Python 엔진에서만** 처리한다. 웹(JS) 타이머로 송신 시점을 정하지 않는다. |
| R-COM-2 | 웹은 송신 요청만 보낸다. 웹에서 CAN 프레임 바이트를 직접 만들지 않는다. |
| R-COM-3 | 수신값은 신호별 최신값을 20~50ms 주기 스냅샷으로 웹에 보낸다. 프레임마다 보내지 않는다. |
| R-COM-4 | 시퀀스 RCV 판정은 기존처럼 실제 수신 프레임으로만 한다. 화면 표시값으로 판정하지 않는다. |
| R-COM-5 | 오류 프레임, 송신 실패 프레임은 표시 대상에서 제외한다. |

### 7.2 송신 패킷 (R-PKT)

| ID | 규칙 |
|---|---|
| R-PKT-1 | 송신 도구는 반드시 등록 패킷을 참조한다. 같은 BUS + CAN ID는 하나의 등록 패킷만 허용한다. |
| R-PKT-2 | 같은 패킷을 쓰는 도구들은 하나의 패킷 데이터를 공유한다(신호 동기화). |
| R-PKT-3 | 주기, 카운터, CRC는 **패킷 단위 설정**이다. 도구 입력창에서는 [이 도구] / [공유 패킷: 이름, 사용 도구 N개] 구역을 나눠 보여준다. |
| R-PKT-4 | 송신 순서는 기존과 같이 최신 값 → 카운터 → CRC → 송신이다. |
| R-PKT-5 | BUS 미선택 패킷은 저장할 수 있으나 송신은 막는다. |
| R-PKT-6 | 패킷 입력창에 카운터·CRC 적용 후의 **송신 바이트 미리보기**를 제공한다. |

### 7.3 INIT (R-INIT)

| ID | 규칙 |
|---|---|
| R-INIT-1 | INIT 사용 여부는 패널별로 선택한다. 사용하지 않으면 기본값은 전체 STOP 한 단계다. |
| R-INIT-2 | INIT 단계는 CMD, DEL, START, STOP, (신규) CYCLE만 허용한다. RCV는 허용하지 않는다. |
| R-INIT-3 | INIT 실행 중에는 송신 도구 조작을 막고, 완료 후 허용한다. |
| R-INIT-4 | INIT 진행 상태를 단계별 체크리스트로 표시하고, 실패 시 실패 단계를 표시한다. |

### 7.4 도구 공통 (R-TOOL)

| ID | 규칙 |
|---|---|
| R-TOOL-1 | 기존 13종 도구는 같은 동작으로 1:1 이식한다. 기존 v5 패널 파일을 그대로 열 수 있어야 한다. |
| R-TOOL-2 | 멀티 명령은 button, toggle, slider와 신규 송신 도구 중 명시된 것에서만 지원한다. 순서·딜레이·응답 확인이 필요하면 시퀀스를 쓴다. |
| R-TOOL-3 | 송신 도구에 필수 값이 비어 있으면 ⚠ 미설정 표시를 하고 RUN을 막는다. ⚠ 목록에서 클릭하면 해당 입력으로 이동한다. |
| R-TOOL-4 | 이미지형 송신 도구(핸들, 페달 등)는 숫자 입력칸과 ± 버튼을 함께 제공한다. |
| R-TOOL-5 | 송신 도구 아래 또는 옆에 현재 송신값을 숫자로 표시한다. |

### 7.5 이벤트 색상 (R-CLR)

| ID | 규칙 |
|---|---|
| R-CLR-1 | 색상 규칙은 도구별 목록으로 저장하고 우선순위가 높은 규칙부터 판정한다. 처음 맞는 규칙 하나만 적용한다. |
| R-CLR-2 | 조건은 비교, 범위, ENUM 값, 수신 끊김을 지원한다. ENUM RAW와 물리값을 구분한다. |
| R-CLR-3 | 맞는 규칙이 없으면 도구 기본색을 쓴다. |
| R-CLR-4 | 수신 끊김은 다른 규칙보다 우선하며 기본 표현은 흐리게 표시다. |
| R-CLR-5 | 편집 중 색상 변경은 미리보기로 보여주고 적용(Apply) 시에만 저장한다. |

### 7.6 AI 생성 (R-AI)

| ID | 규칙 |
|---|---|
| R-AI-1 | AI 출력은 **패널 정의 JSON만** 허용한다. HTML, JS 등 실행 코드는 받지 않는다. |
| R-AI-2 | AI는 앱이 지원하는 도구 목록 안에서만 고른다. 목록 밖 요청은 "지원 안 됨"으로 알린다. |
| R-AI-3 | AI는 카운터, CRC, 주기, 송신 값, 범위를 **추측하지 않고 미설정으로 남긴다**. |
| R-AI-4 | 비트 위치, 스케일, 오프셋은 AI가 아니라 앱이 로컬 DBC에서 채운다. |
| R-AI-5 | 신호의 의미가 모호하거나 후보가 여러 개면 임의로 고르지 않고 질문한다. |
| R-AI-6 | AI에 보내는 정보는 선택한 신호의 신호명, 메시지명, CAN ID, 단위, 범위, ENUM 이름, 송수신 구분으로 제한한다. DBC 파일 전체는 보내지 않는다. |
| R-AI-7 | AI 결과는 앱의 검증을 통과해야 미리보기로 넘어간다. 미리보기 단계에서는 송신하지 않는다. |
| R-AI-8 | 적용한 결과는 일반 편집과 같이 실행 취소할 수 있다. |

### 7.7 안전 (R-SAFE)

| ID | 규칙 |
|---|---|
| R-SAFE-1 | 상단 고정줄에 모드, INIT 상태, 송신 중 패킷 수, **전체 정지 버튼(Esc)** 을 항상 표시한다. |
| R-SAFE-2 | 누름/놓음 동작 도구는 창 포커스를 잃거나 포인터가 취소되면 놓음 값으로 복귀한다. |
| R-SAFE-3 | 위험 동작(지정한 시퀀스 등)은 길게 눌러 실행하는 옵션을 제공한다. |
| R-SAFE-4 | 이미지형 송신 도구는 조작 잠금 옵션과 변화량 제한을 제공한다. |
| R-SAFE-5 | 웹 화면은 엔진이 허용한 동작만 활성화한다. 모드 판정은 엔진에서 한다. |

### 7.8 편집과 배포 (R-DEP)

| ID | 규칙 |
|---|---|
| R-DEP-1 | **만드는 사람**(메인창 + EDIT)과 **쓰는 사람**(패널 전용 앱)을 분리한다. |
| R-DEP-2 | 패널 전용 앱에서는 CRC, 카운터, 패킷 설정을 표시하거나 수정하지 않는다. |
| R-DEP-3 | 배포는 완성된 `.pjjupkg`로 한다. 쓰는 사람은 AI 없이 패키지를 열어 사용한다. |
| R-DEP-4 | 웹 라이브러리는 exe에 포함한다. 인터넷 없이 동작해야 한다(AI 생성 제외). |

### 7.9 호환과 검증 (R-VAL)

| ID | 규칙 |
|---|---|
| R-VAL-1 | 검증은 Python 한 곳(`validate_packet`, `validate_tool`, `validate_steps` 등)에서만 한다. 웹은 결과만 표시한다. |
| R-VAL-2 | 파일 형식은 `.upp.json` v6으로 올리되 v5 파일 읽기를 유지한다. |
| R-VAL-3 | 전환 기간에는 Qt 패널과 웹 패널이 같은 엔진과 같은 파일을 공유한다. |
| R-VAL-4 | 기존 인수 체크리스트와 엔진 자동 테스트를 웹 패널 검증 기준으로 사용한다. |

## 8. 의견

1. **전환은 가능하고, 방향도 맞습니다.** 패널 정의가 이미 JSON으로 분리되어 있고 웹 AI 생성 가이드도 있어서, 웹 전환과 AI 생성 모두 기반이 마련된 상태입니다.
2. **생성 결과의 수준은 AI가 아니라 도구 라이브러리가 정합니다.** 지금 AI 생성 결과가 입력 양식처럼 보이는 이유는 표현할 도구가 부족해서입니다. 투자의 중심은 AI 연동보다 **도구와 컨셉 템플릿**이어야 합니다.
3. **송신 세부값은 사람이 입력하는 구조가 맞습니다.** AI는 틀만 만들고 송신 세부값은 미설정으로 남기는 규칙(R-AI-3)이 안전성과 신뢰성의 핵심입니다.
4. **엔진은 건드리지 않는 것을 원칙으로 합니다.** 엔진에 꼭 필요한 추가는 INIT 주기 변경(CYCLE)과 엔진 모듈의 Qt 분리 정도로 한정합니다.
5. **패널 전용 앱에서 CRC 검증 기능은 필요하지 않습니다.** 만드는 단계에서 송신 바이트 미리보기로 확인하면 충분합니다. 실차 로그와 CRC 비교 기능과 수신 CRC 검증은 필요가 생기면 추가합니다.
6. **작업량의 대부분은 웹 편집기입니다.** 런타임 화면보다 편집기(배치, 속성, 시퀀스·INIT 편집)가 큽니다. 보기 전용부터 단계적으로 진행하는 것이 안전합니다.

## 9. 단계별 진행안

| 단계 | 범위 | 확인할 것 |
|---|---|---|
| 1 | 웹 보기 전용 뷰어: v5 패널을 웹에서 표시, 수신값 갱신 | 성능, exe 크기, 저사양 PC 렌더링 |
| 2 | 송신 도구 연결: 단독·멀티·시퀀스·INIT 실행, 안전 규칙(R-SAFE) | 기존 인수 체크리스트 통과 |
| 3 | 신규 도구와 이벤트 색상, 탭/패널 확장 | 도구별 동작 |
| 4 | 웹 편집기: 배치, 속성, 패킷·카운터·CRC 입력, INIT(CYCLE 포함), 시퀀스 편집 | Qt 편집기와 같은 결과 |
| 5 | 템플릿 생성(오프라인) → 복사/붙여넣기 AI → 중계 서버 API | 생성 결과 검증, 미설정 처리 |
| 6 | 패널 전용 앱 배포 형태 정리, Qt 패널 종료 시점 결정 | 현장 검증 |

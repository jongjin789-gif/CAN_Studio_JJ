# CAN Studio JJ 프로젝트 평가 (R013 기준)

- 작성일: 2026-11-11
- 대상: `main` 브랜치 (커밋 22b3c5c)
- 갱신: 2026-11-11, [높음] 1·2번 수정 반영 (7장 참고)

## 1. 요약

PCAN 모니터로 시작해 DBC 디코딩, 송신, 로그 기록·뷰어, 그래프, 유저 패널, 멀티 디바이스까지 확장되었다.
현재는 **사내용 경량 CAN 분석/시험 도구** 수준이며, 기능 폭에 비해 테스트와 문서가 잘 갖춰져 있다.
다만 **고부하 버스 성능**과 **실시간 그래프 정확도**에 구조적 한계가 있다.
이 중 실시간 그래프 정확도 문제는 수정을 마쳤고, 고부하 성능(수신 배치 처리)은 다음 작업으로 남아 있다.

## 3. 강점

- **장치 추상화**: `CanDeviceBackend` 계약으로 장치 추가 시 나머지 코드 수정 불필요. S/N 기반 채널 재탐색 등 현장 문제 고려.
- **로그 포맷 호환성**: TRC 1.0~2.x, PCAN-View/Explorer 변형, ASC/BLF, CL2000 TXT 지원.
- **실무 기능**: Hyundai CRC/Counter, 게이트웨이, 트리거 캡처, 타임아웃 알림, 버스 부하율, 오류 카운터, 로그 재전송.
- **유저 패널**: 시퀀스, 조건부 색상, Undo/Redo, 페이지 탭 등 HMI 빌더 수준. 가장 큰 차별점.
- **운영 편의**: 세션 자동 복원, 레거시 파일 마이그레이션, 뷰어 전용 모드.

## 7. 수정 이력

### 7.1 [높음] 항목별 수정량 평가

| # | 문제 | 수정량 | 수정 범위 | 회귀 위험 |
|---|---|---|---|---|
| 2 | 로그 재생 O(n²) | 아주 작음 (3~5줄) | `log_viewer.py` 한 곳 | 거의 없음 |
| 1 | 실시간 그래프 20 Hz 제한 | 중간 (약 50~80줄) | 소스 2개 + 테스트 | 중간 |
| 3 | 프레임마다 시그널 전송 | 큼 (약 150~300줄) | 소스 4~5개 + 테스트 4개 파일 | 높음 |

3번이 큰 이유:
- `raw_msg_signal` 형식을 바꾸면 이 시그널을 받는 쪽(기록, 트리거, 부하율, 유저 패널 시퀀스 수신, 게이트웨이 표시)을 모두 고쳐야 한다.
- 기록 파일 쓰기를 별도 스레드로 옮기는 작업이 추가된다.
- 시퀀스 RCV 대기처럼 타이밍에 민감한 동작이 배치 단위(10~20 ms)로 늦어질 수 있어 실장비 검증이 필요하다.

### 7.2 2026-11-11 수정 내용

**1번: 실시간 그래프 20 Hz 제한 (수정 완료)**
- `src/main_window.py`
  - `_graph_pending_frames`가 ID별 최신값 하나 대신, 틱 사이의 프레임 목록을 모으도록 변경.
  - `update_bound_graphs`가 모은 프레임을 시간순으로 전부 디코딩해 그래프에 넣도록 변경. 한 프레임의 디코딩 결과는 여러 그래프가 공유.
- `src/graph_realtime.py`
  - `begin_batch()`/`end_batch()` 추가. 묶음 처리 중에는 샘플만 쌓고, 곡선은 틱마다 한 번만 다시 그림.
  - 샘플을 하나씩 순서대로 넣으므로 수식(Y1~Y3) 계산 결과는 기존과 같다.

**2번: 로그 재생 O(n²) (수정 완료)**
- `src/log_viewer.py:811`의 `list.index()` 반복을 객체 id 기반 dict 조회(O(n))로 변경.
- 정정: `_send_rows`는 송신 시작 시 이미 올바르게 만들어지므로, 이 분기는 정상 흐름에서 실행되지 않는다. 실제 위험도는 "낮음"이다.

### 7.3 검증 결과

- 회귀 테스트 2개 추가 (`tests/test_graph_realtime_ranges.py`)
